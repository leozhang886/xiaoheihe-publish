## 一、要解决的问题

把 Markdown 文章自动发布到小黑盒，并且**参与「文章计划」拿创作激励**。

发布页面有三个必填项，缺一个就发不出去：

| 必填项 | 说明 |
|---|---|
| 权限设置 | 所有人可见 |
| 内容声明 | 原创 |
| **内容封面** | **独立字段，不是正文首图。为空时点「发布」静默失败** |
| 选择计划 | 勾了「创作计划」后，必须在「文章计划 / 热点计划」二选一 |

**最坑的一点：封面为空时，点「发布」没有任何反应**——没有 toast、没有 disabled 状态、URL 不变。纯静默失败。

## 三、真正的卡点

**「内容封面」出现之后的下一行 `page.evaluate` 就崩了。**

具体报错：

```
page.evaluate: Target page, context or browser has been closed
```

崩溃发生在这一步（代码见 `tools/cover-publish.mjs`）：

```js
await page.evaluate(() => {
  const lbl = [...document.querySelectorAll('.creator-editor__form-label')].find(
    (e) => (e.textContent || '').trim() === '内容封面'
  );
  lbl?.closest('.creator-editor__form-item')?.scrollIntoView({ block: 'center' });
});
```

**上一步刚成功找到「内容封面」，紧接着的 evaluate 就报页面已关闭。**

不是选择器问题，是**浏览器/页面本身没了**。

## 五、怀疑的崩溃原因（按可能性排序）

1. **浏览器被外部关闭**
   每轮工具调用结束后，后台进程被回收，连带 Chromium 退出。
   日志里已经出现十几次 `BROWSER_CLOSED`。

2. **页面崩溃（renderer crash）**
   这个编辑器页是重度 SPA，滚动 + 反复 evaluate 可能触发渲染进程崩溃。
   建议加 `page.on('crash')` 和 `page.on('close')` 监听，定位到底是谁关的。

3. **触发了风控/验证码**
   用户反馈「现在要搞验证码了」。
   平台在高频操作后会弹点击验证，页面可能跳到验证页或被强制关闭。

4. **persistent profile 锁冲突**
   `chromium.launchPersistentContext(PROFILE)` 用了 `profile/` 目录。
   如果已有 Chromium 占着这个目录，行为会不稳定。

## 八、给 Codex 的建议排查步骤

1. **先确认是谁关的浏览器**
   ```js
   page.on('crash', () => console.log('PAGE CRASH'));
   page.on('close', () => console.log('PAGE CLOSE'));
   ctx.on('close', () => console.log('CTX CLOSE'));
   ```
   在崩溃前打日志，就知道是被外部杀、还是渲染崩了。

2. **确认 profile 没被占**
   跑之前先确认 9222 没在监听、没有 Chromium 占着 `profile/`。

3. **把崩溃点前后的操作拆开重试**
   「内容封面」出现后，先 `sleep(3000)` 再 evaluate，看是不是时序问题。

4. **换个思路：不走 hover**
   既然 `input[type=file]` 存在于弹窗里，可以试试直接 `page.setInputFiles`（Playwright 支持对隐藏 input 直接设文件），不用先点「修改封面」。

5. **最省事的兜底**
   用 `codegen` 录制一次手动上传封面的完整操作，导出脚本，再套进现有流程。

## 十、接手核对补充（2026-10-30）

- 只读检查 `tools/cover-publish.mjs` 后确认：脚本没有注册 `page` 崩溃、关闭或 `ctx` 关闭事件监听；异常会被 `catch` 记录，随后 `finally` 总会主动调用 `ctx.close()`。因此，下一次即使看到 `CTX CLOSE`，也须标记这次关闭是否由脚本自己触发，不能单凭该事件认定是外部杀进程。
- `page.evaluate: Target page, context or browser has been closed` 只说明执行该调用时目标已关闭；触发关闭的原因尚未确认。可同时记录 `PAGE CRASH`、`PAGE CLOSE`、`CTX CLOSE` 的时间和脚本主动关闭标志，再比对报错顺序。
