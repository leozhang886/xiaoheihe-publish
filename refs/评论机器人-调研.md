# 小黑盒评论自动回复 —— 开源项目调研

> 调研时间：2026-09　用途：**回复自己帖子下的评论**

## 结论

用 **[Whereis-Alice/astrbot_plugin_xhhrobot](https://github.com/Whereis-Alice/astrbot_plugin_xhhrobot)**
（AstrBot 插件，Python，MIT，最后更新 2026-08-27）。

它是唯一一个**原生支持"只回自己帖子评论"**、并且明确写了不回别人帖子的项目。

## 技术路线：它们都不是浏览器自动化

这些项目**全都在逆向小黑盒 App 的接口**（自己算 `hkey` / `nonce` / `timestamp` 签名，轮询消息），
和我之前给小熊盒写文章用的 CDP/Playwright 方案完全不同。

| | App 接口方案 | 浏览器自动化（我做的） |
|---|---|---|
| 部署 | 二进制或 Python，可挂服务器 24h | 必须有浏览器窗口开着 |
| 速度 | 快，轮询 | 慢，要等页面渲染 |
| 稳定性 | **接口一变就废** | 页面结构变了才废 |
| 风控 | 同样触发 | 同样触发 |

## 推荐项目：回复范围（官方 README 原文）

| 场景 | 行为 |
|---|---|
| 用户在任意帖子中明确提及机器人 | 通过允许范围检查后回复 |
| **用户在机器人自己发布的帖子下普通评论** | **开启「回复自己帖子下的普通评论」后回复，无需 @** |
| 用户在其他账号帖子下普通评论 | **不回复** |
| 机器人自己的评论 | 忽略，避免自我回复循环 |

## 环境要求

- **AstrBot `>=4.24.5,<5`**（插件运行在 AstrBot 框架内）
- Python 3.10+
- 一个可用的小黑盒账号
- AstrBot 里已配置的 LLM 提供商（要识别图片需支持视觉输入）

安装：AstrBot 插件管理页填仓库地址 `https://github.com/Whereis-Alice/astrbot_plugin_xhhrobot`
（或下载 Release，手动放到 `data/plugins/`）

## 针对「回自己帖子评论」的配置

| 配置页中文名 | 配置键 | 建议值 |
|---|---|---|
| 回复模型 | `ai.provider_id` | 选负责回复的模型 |
| 回复人设 | `ai.persona_id` | 建议单独建一个「盒友风格」人设 |
| **回复自己帖子下的普通评论** | `filters.reply_to_own_post_comments` | **开启**（核心） |
| **单个自己帖子自动回复上限** | `filters.max_replies_per_own_post` | **3~5**，别用 0（不限）——热帖会堆爆队列 |
| 允许回复的用户 ID | `filters.allowed_user_ids` | 先只填几个测试用户 |
| 允许回复所有用户 | `filters.allow_all_users` | **测试稳定后再开** |
| 允许回复的用户 ID（黑名单） | `filters.deny_user_ids` | 屏蔽列表优先级最高 |
| **启用自动巡帖** | — | **保持关闭**（最危险的功能） |
| 启用私信自动回复 | — | 按需，默认关 |
| 每次写操作都要求确认 | — | 前期建议**开启**，观察一段时间再关 |
| 允许回复时使用外部搜索 | `ai.allow_external_search` | 按需 |

## 上线流程（从小范围开始）

1. 装 AstrBot + 插件
2. WebUI 里生成二维码 → **手机小黑盒 App 扫码登录**
   （或管理员发 `/小黑盒登录`）
3. `/小黑盒状态` 确认登录和后台任务
4. **只填允许列表**，`allow_all_users` 保持关闭
5. **先干跑，不发**：
   ```
   /小黑盒测试 帖子ID 测试消息      # 生成回复但不发布
   /小黑盒检查                      # 立即跑一轮检查
   ```
6. 确认口吻满意后，再开启写操作
7. 观察几天，逐步放开

### 常用管理指令

| 指令 | 作用 |
|---|---|
| `/小黑盒登录` / `/小黑盒退出` | 扫码登录 / 清除凭据 |
| `/小黑盒状态` | 看账号、后台任务、队列 |
| `/小黑盒启动` / `/小黑盒停止` | 开关后台轮询 |
| `/小黑盒检查` | 立即执行一轮评论检查 |
| `/小黑盒清空队列 帖子ID 确认` | 取消指定帖子未发送的回复 |
| `/小黑盒重试` | 失败记录重新入队（`确认` 版可能重复发送） |

## ⚠️ 风险与注意事项

### 项目作者自己的警告（README 原文）

> 本插件使用的**不是小黑盒面向第三方开放的稳定公共 API**。
> 接口变化、账号状态和平台风控都可能影响功能。
> 建议先使用测试账号和用户允许列表，并保持较低频率。

### 实际风险

1. **接口随时可能失效** —— 小黑盒改了签名算法，项目就废了
2. **账号可能被风控** —— 自动回复是典型的风控特征。我们实测过：只在编辑器里反复操作就弹了 5 次验证码
3. **热帖会堆队列** —— 一条爆帖几百条评论，全自动回会瞬间暴露。**必须设 `max_replies_per_own_post`**
4. **官方建议**：
   > 平台已经提示评论频率异常时，应等待限制自然解除，**不要反复重试**。

### 插件内置的保护（保留默认，别关）

- 写入权限开关 / 可选逐次确认
- 写入冷却 + 随机轮询 + 单用户冷却 + 24 小时额度
- 消息去重 / 单帖回复上限
- 发送结果不确定保护（防止重试导致重复发送）
- 收到「禁止发送消息行为」时自动跳过并暂停外发

### 还有一条不是技术问题

读者可能不喜欢被告知在跟 AI 说话，也可能**不喜欢事后才发现**。
建议：人设做得像真人没什么问题，但**别否认是 AI**——被拆穿比一开始就说清楚代价大得多。

---

## 不推荐的做法

**「自主巡帖 + 自动评论别人帖子」**（`heibox-comment-bot` 和 AstrBot 插件的巡帖模式都支持）。

那是主动到陌生人帖子里留言，性质接近骚扰，是这几个项目里最容易导致封号的用法。
AstrBot 插件默认就把巡帖关着，并强制要求先跑「预览」——**尊重这个默认值**。
