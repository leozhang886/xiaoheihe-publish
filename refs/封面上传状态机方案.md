## 2. 故障根因

### 2.1 【事实】诊断时机错误

- L403：`await page.reload(...)` —— 销毁弹窗
- L426-427：`screenshot` + `dumpState` —— **在重载之后**

**因此 `state-no-chooser-*.json` 记录的是重载后的页面。**

这解释了三个"矛盾"：

| JSON | 真实含义 |
|---|---|
| `hasMask:false` | 重载后弹窗已销毁 |
| `hasBanner:true` | 重载后提示重新出现 |
| `hasPublishPanel:true` | 重载后正常渲染 |

**结论：该证据不能代表故障瞬间。它是有用的重载后快照，不是故障现场。**

### 2.2 【事实】日志谎报

L247-251：

```js
if (!planOn) {
  await page.click('.creation-plan-join .switch__button', { timeout: 8000 }).catch(() => {});
  await sleep(2000);
}
log('创作计划: 参与');    // 无条件打印
```

点击失败被 `.catch(() => {})` 吞掉，随后无条件打日志，**无复检**。

用户截图中「创作计划：不参与」与日志「参与」并存，即为直接后果。

### 2.3 【事实】计划选择只验证"点过"

L254-291 返回的 `'clicked'` 仅代表调用了 `el.click()`，**未读取任何选中状态**。

L400-424：filechooser 失败 → `page.reload()`。

## 4. 图片身份关联（修订 v2.1，回应复审第 2、3 条）

### 4.1 撤销 v1 的错误判断

**v1 的「`blob:` 说明是本次刚选的文件」不成立。**

`blob:` 只表示"内存对象 URL"。任何人、任何时刻打开裁剪弹窗都可能产生。用户此前手动上传的图同样是 `blob:`。

**`http(s):` 也不能单独证明是历史图片** —— 某些实现保存后会回写 `https`。

**两者都不能作为身份判据。**

### 4.2 两个阶段分开定义（回应复审第 3 条的循环定义）

v2 把「保存动作」也写进因果链，又要求 L1 在保存前成立 —— **循环定义**。

修订：**拆成"保存前"与"保存后"两段。**

#### 4.2.1 保存前：上传关联（pre-save binding）

要建立联系，**必须同时具备以下四项**，缺一项即"上传身份未知"：

| 项 | 内容 | 取法 |
|---|---|---|
| B1 | **目标弹窗实例** | 打开弹窗时记录的 `maskElement` 引用（WeakRef / 元素句柄），后续校验 `isConnected` |
| B2 | **该弹窗内的文件输入控件** | `maskElement.querySelector('input[type=file]')`，记录元素句柄 |
| B3 | **本次提交的文件** | `setInputFiles()` 或 `filechooser.setFiles()` 的入参路径 + 文件 `sha256` |
| B4 | **该控件对应的预览变化** | 在 B2 的元素上监听 `change` 事件，事件触发后**同一弹窗内**出现的新 `img` |

**关键修正（回应复审第 3 条）：**

> 「`setFiles` 之后出现的新 `<img>` 即本次目标图」**不成立**。
> - 可能是**旧请求延迟返回**的图片
> - 正常上传也可能**复用原有 img 元素**（只改 `src`）

**因此判据改为：**

```
上传关联成立 =
    B1 弹窗仍是同一个实例
  ∧ B2 输入控件存在且可写
  ∧ B3 change 事件在本次操作后触发
  ∧ B4 该 img 的 src 在 change 事件之后发生变化（新元素或 src 改变均可）
  ∧ 该 img 属于 B1 弹窗的可见裁剪区
```

**任一不成立 → 上传身份未知 → 阻断。**

> ⚠️ **本规则为「候选关联」，状态：待验证。不得据此点「确定」。**
>
> 它**不能排除**「旧请求在本次 change 之后返回」：旧结果同样可能出现在同一弹窗、在同一次 change 之后。B4 只能证明"图片变了"，不能证明"变的是我这次传的那张"。
>
> **在取得能区分「本次上传」与「旧结果」的证据前，L1 保持未知**，不允许点「确定」。
> 反例用例见 §9.4 A19。
>
> 可能需要的新证据方向（均为**【待验证】**，本稿不假设其存在）：
> - 上传请求与响应的 requestId / 时序关联
> - 控件 `change` 事件携带的 `File` 对象与目标文件 `sha256` 一致
> - 预览元素的创建时间戳晚于 change 时间戳**且**其来源请求可识别

#### 4.2.2 保存后：结果关联（post-save binding）

点「确定」之后，记录：

```
保存结果关联 =
    封面行 img 的 src（保存后读取）
  ∧ 保存动作发生的时间戳
  ∧ 保存时使用的那次上传关联标识（B3 的 sha256）
```

**这两段必须分别记录，不得混为一条链。**

### 4.3 三种情形

| 情形 | 判定 | 允许动作 |
|---|---|---|
| **A. 本进程内完成上传，4.2.1 候选关联成立** | **候选关联成立 ≠ 上传身份已确认** | **禁止点「确定」**；L1 保持未知，报 `UNKNOWN`（退出码 9） |
| **B. 进入页面时弹窗已开** | 无 B3/B4 记录 | **停在 UNKNOWN，不点确定、不点取消、不跳过**，退出码 9 |
| **C. 上传关联部分成立** | 缺任一项 | 同上，阻断 |

### 4.3.1 统一规则（全文适用）

**候选关联成立，不等于上传身份已确认。**

**在取得并验证「能区分本次上传与旧结果」的证据之前：**

- L1 **保持未知**
- **禁止点「确定」**
- 报 `UNKNOWN`，退出码 9
- 依赖 L1 的上传成功用例（场景 1、场景 3、A4b、A5）**保留为未来验收目标**，当前标注「**前置证据未满足，未验证**」，**不得声称已通过**

**不得自行编造证据，不得假定某个接口或字段存在。**

### 4.4 封面映射（回应复审第 2 条）

#### 4.4.1 记录结构

```json
{
  "account": "<账号标识>",
  "draftId": "196639165",
  "targetFile": { "path": "...", "sha256": "...", "size": 123456 },
  "savedSrc": "https://imgheybox.max-c.com/....png",
  "savedAt": "2026-11-11T12:00:00+08:00",
  "confirmedLevel": 4,
  "pageReadbackAt": "2026-11-11T12:00:05+08:00"
}
```

#### 4.4.2 `COVER_SAME` 需要四个条件，不是三个

**v2 只用「账号 + 草稿 + 指纹」相等，不足以证明当前封面就是它。**

**复审指出的漏洞：** 用户后来手动换了封面，旧映射仍满足这三条，会错误跳过上传。

**修订为四项全等：**

```
COVER_SAME =
    account 相同
  ∧ draftId 相同
  ∧ targetFile.sha256 相同
  ∧ 【新增】当前页面封面 img.src === 记录中的 savedSrc
```

**第四项是关键**：它把历史记录和**当前页面实际显示**绑在一起。

**判定顺序（重要）：先验记录有效性，再比指纹。** 不得反过来。

```
第一步  记录有效性与「是否对应当前封面」
        ├─ account / draftId 不符            → COVER_IDENTITY_UNKNOWN
        ├─ sha256 缺失（仅文件名）           → COVER_IDENTITY_UNKNOWN
        ├─ savedSrc 缺失或与当前页面 img.src 不符 → COVER_IDENTITY_UNKNOWN
        ├─ confirmedLevel < 4                → COVER_IDENTITY_UNKNOWN
        └─ 记录已过失效条件（4.4.3）          → COVER_IDENTITY_UNKNOWN

第二步  只有在第一步全部通过后，才比较目标指纹
        ├─ sha256 相同 → COVER_SAME
        └─ sha256 不同 → COVER_DIFFERENT
```

**不要使用「四项不全等一律 UNKNOWN」这种概括**——它与「记录有效但指纹不同 → DIFFERENT」冲突。

#### 4.4.3 映射失效条件（v2 未定义，此处补齐）

记录视为**失效**，按 `COVER_IDENTITY_UNKNOWN` 处理，当：

| 失效条件 | 说明 |
|---|---|
| `draftId` 不存在于记录 | 从未记录 |
| `account` 与当前不符 | 换号 |
| `sha256` 缺失或只有文件名 | 无法比对内容 |
| `savedSrc` 缺失 | 无法与页面比对 |
| `confirmedLevel < 4` | 保存未被确认 |
| `savedAt` 早于 `pageReadbackAt` 的最近一次封面变更 | 页面上封面在记录之后被改过 |
| 记录格式版本不识别 | 结构变更 |

**「过期」的含义即上表，不再是模糊措辞。**

#### 4.4.4 `COVER_DIFFERENT` 的成立前提

**「指纹不同 → DIFFERENT」只在"记录确实对应当前封面"的前提下成立。**

```
COVER_DIFFERENT =
    account / draftId / 已确认 savedSrc 三者与当前页面吻合
  ∧ targetFile.sha256 ≠ 记录的 sha256
```

**如果记录与当前页面对不上** → 进入 `COVER_IDENTITY_UNKNOWN`，**不得据此判定"不同"并覆盖上传**。

### 4.5 保存确认的四级判据（去掉循环）

v2 的 L1 引用了包含保存动作的链路，与「保存前」冲突。修订：

| 级别 | 名称 | 判据 | 时机 | 能证明什么 |
|---|---|---|---|---|
| **L1** | 上传身份已确认 | **§4.2.1 候选关联全成立 _且_ 具备「区分本次上传与旧结果」的证据**（当前**无此证据**）→ 因此 **L1 现状恒为未知** | **保存前** | 这是本次要传的图 |
| **L2** | 图片已加载 | 目标裁剪区 img：`complete === true` ∧ `naturalWidth > 0` | 保存前 | 预览可用 |
| **L3** | 保存动作已执行 | 「确定」已点击 ∧ 弹窗关闭 | 保存时 | 点了按钮且弹窗关闭（**仅当 L1 已确认时才允许走到这一步**） |
| **L4** | 页面预览已更新 | 封面行 img.src 与保存前不同 ∧ 非 `blob:` | 保存后 | **页面显示变了** |

**L4 ≠ 服务器已持久保存。** 无接口证据前，「持久保存」标 **【待验证】**。

**关于 L1 的当前状态（重要）：**

由于 §4.3.1 的「区分证据」尚未取得，**L1 恒为未知**，因此：

| 用例 | 原本依赖 | 当前状态 |
|---|---|---|
| 场景 1（无封面→上传） | L1→L2→L3→L4 | **前置证据未满足，未验证** |
| 场景 3（不同封面→替换） | 同上 | **前置证据未满足，未验证** |
| A4b（完整替换） | 同上 | **前置证据未满足，未验证** |
| A5（旧封面 http 但保存失败） | L4 | **可验识别部分，动作部分未验证** |

**上述用例保留为未来验收目标，不得声称已通过。**



## 5. 状态机（修订 v2.1，回应复审第 4、5 条）

### 5.1 三层优先 + 写前闸

```
第 0 层  写前闸（每次写操作前都要过，命中即停）
          ├─ MODE_FORBIDDEN     当前为 --readonly
          ├─ TARGET_MISMATCH    目标不是指定草稿
          ├─ PUBLISH_MODE_NOT_OK  发布模式 ≠ CONFIRMED_UNPUBLISHED
          ├─ STALE_PROMPT       可能存在本地未保存内容
          └─ CAPTCHA            验证码可见

第 1 层  编辑器就绪（不依赖计划选择结果）
第 2 层  业务状态（计划 / 封面）
```

**回应复审第 5 条：** v2 只在最终发布时拦截 `CONFIRMED_PUBLISHED` 和 `UNKNOWN`，**与 A8「未知发布模式零写操作」不一致**。

**修订：`PUBLISH_MODE_NOT_OK` 进入第 0 层**，即 `CONFIRMED_PUBLISHED` 与 `UNKNOWN` **都在第一次写操作之前阻断**，不只是发布前。

### 5.2 每次写操作前的复核（回应复审第 5 条）

v2 只要求"写后重读"。修订为**写前 + 写后双向**：

每次写操作（点击开关、点单选、开弹窗、setFiles、点确定）**之前**，重新检查：

| 检查 | 不通过 |
|---|---|
| 运行模式（`--readonly`） | 中止，退出码 12 |
| 目标账号 / 草稿 | 中止，退出码 2 |
| 发布模式 | 中止，退出码 2 |
| 本地恢复提示 | 中止，退出码 6 |

**提示在流程中途出现时，立即停止后续写操作**，不等最终发布前才拦。

## 6. 创作计划复检（回应审查第 4 条）

### 6.1 统一为「且」，撤销 v1 的「或」

**v1 的矛盾：** L250 写「选中 **并且** 字段出现」，L277 写「选中 **或者** 字段出现」。

**「或」会产生虚假成功** —— 字段出现本身不代表目标计划被选中（可能是上次残留）。

**修订为：**

```
PLAN_SELECTED = planRadioChecked && coverFieldVisible
```

- `planRadioChecked` 是**必要条件**
- `coverFieldVisible` 仅作**辅助交叉验证**
- 只有「字段出现」而无「单选选中」→ **判为未选中**

### 6.2 选择器必须限定到目标计划的实际控件

v1 用 `.radio__select-label, label, span` 加文本比对，**可能命中附近无关控件**。

修订：

```js
const state = await page.evaluate((want) => {
  // 只在「选择计划」这一行里找
  const row = [...document.querySelectorAll('.creator-editor__form-item')].find((it) =>
    (it.querySelector('.creator-editor__form-label')?.textContent || '').trim() === '选择计划'
  );
  if (!row) return 'no-row';
  const labels = [...row.querySelectorAll('.radio__select-label, label')];
  const hit = labels.find((e) => (e.textContent || '').trim() === want);
  if (!hit) return 'no-label';
  // 读目标控件自身的选中态，不读兄弟节点
  const box = hit.closest('.radio') || hit.parentElement;
  const checked =
    !!box?.querySelector('.radio__box.checked, .radio__box.active') ||
    !!box?.querySelector('input[type=radio]:checked');
  return checked ? 'checked' : 'unchecked';
}, PLAN_LABEL);
```

### 6.3 原本已开启的开关也要复检

v1 只在不 active 时才点，**且点完不复检**（L247-251）。

修订：

```js
// 先读当前状态
let active = await readPlanSwitch();
if (!active) {
  await page.click('.creation-plan-join .switch__button', { timeout: 8000 });
  await sleep(1500);
  active = await readPlanSwitch();          // 重读
}
if (!active) throw new Error('创作计划未处于参与状态');
log('创作计划: 已确认参与');
```

**「原本就 active」的路径同样要打印「已确认」，因为它也是读出来的。**

### 6.4 重试规则：只在「尚未达到目标」时点

**避免重复点击把开关关掉。**

```
if (当前状态 !== 目标状态) 才点击
每次点击后重读
最多 N 次
N 次后仍不达标 → 抛错
```

## 8. 诊断（回应审查第 7 条）

### 8.1 事件流水，不是单点快照

v1 只在最终失败时转储一次。修订为**每次失败或自救之前**记录一条，形成流水：

```json
{
  "seq": 3,
  "at": "2026-11-11T12:00:00.000+08:00",
  "phase": "UPLOAD",
  "before": { "modalOpen": true, "hasUploadText": false, "imgCount": 1 },
  "attempt": { "action": "click", "target": "点击上传", "result": "not-found" },
  "reason": "目标按钮文案不存在",
  "after":  { "modalOpen": true, "hasUploadText": false, "imgCount": 1 },
  "shot": "shots/evt-0003.png",
  "rescue": null
}
```

**关键：`before` 必须在任何自救动作之前采集。**

### 8.2 截图与 JSON 不是同一时刻

两者先后采集，**不得假定严格同步**。JSON 里记录的 `shotAt` 与 `snapshotAt` 分别打时间戳。

### 8.3 删除自动重载

**v1 L325-326 仍允许「重载」，与 L382-384「删除重载」冲突。**

修订：**统一删除自动重载路径**。任何需要重载的场景，改为报错退出，由人工决定。

### 8.4 诊断自身失败也要停

如果 `dumpState()` 抛错，**不得继续执行后续动作**，直接以退出码 10 结束。

### 8.5 取证边界（回应审查第 7 条后半）

| 约束 | 说明 |
|---|---|
| 只读取当前已加载的数据 | **不主动重放请求** |
| 不制造未保存内容 | 不得为采集证据而故意触发提示 |
| 不切换真实文章状态 | 不得发布/取消发布来做对照 |
| 不整库导出 | 不导出 localStorage / IndexedDB 全量 |
| 脱敏 | 保存前遮盖 token、签名参数、cookie、手机号 |
| 报告截断 | 记录 `truncated: true` 及原始长度，**关键字段单独提取，不依赖截断片段** |

### 8.6 措辞修正

- v1 L90「伪证」→ **「重载后证据，不能代表故障瞬间」**
- v1 L413「本地内容比服务器新」→ **「可能存在本地未保存内容」**（不预设新旧）

### 11.2 白名单采集（只输出明确允许的字段）

**原则：默认不输出，逐字段显式允许。**

```js
// 只读。不点按钮，不发请求，不导出整库存储。
(() => {
  const out = { at: new Date().toISOString() };

  // ---- 1. 来源与路径（不含参数值）----
  const u = new URL(location.href);
  out.origin = u.origin;
  out.path = u.pathname;                       // 只保留路径
  out.paramNames = [...u.searchParams.keys()]; // 只保留参数名，不留值
  out.draftIdFromPath = (u.pathname.match(/article\/(\d+)/) || [])[1] || null;

  // ---- 2. 弹窗结构（只要结构，不要文本）----
  const mask = document.querySelector('.hb-cpt__mask-wrapper');
  out.modal = mask ? {
    connected: mask.isConnected,
    visible: mask.offsetParent !== null,
    childTags: [...mask.querySelectorAll('*')].slice(0, 40).map(e => e.tagName.toLowerCase()),
    hasFileInput: !!mask.querySelector('input[type=file]'),
    imgCount: mask.querySelectorAll('img').length,
    imgSchemes: [...new Set([...mask.querySelectorAll('img')].map(i => (i.src || '').split(':')[0]))],
    imgComplete: [...mask.querySelectorAll('img')].map(i => [i.complete, i.naturalWidth > 0]),
    // 只输出「预先列明的功能词是否存在」，不输出任何其他文字
    knownActionWords: ['点击上传', '上传封面', '拖拽选框裁剪', '取消', '确定'].filter(
      w => (mask.innerText || '').includes(w)
    ),
  } : null;

  // ---- 3. 封面行（只要结构）----
  const row = [...document.querySelectorAll('.creator-editor__form-label')]
    .find(e => (e.textContent || '').trim() === '内容封面')
    ?.closest('.creator-editor__form-item');
  out.coverRow = row ? {
    hasImg: !!row.querySelector('img'),
    imgScheme: row.querySelector('img')?.src?.split(':')[0] || null,
    imgComplete: row.querySelector('img')?.complete ?? null,
    childClasses: [...new Set([...row.querySelectorAll('*')].map(e => e.className).filter(c => typeof c === 'string' && c))].slice(0, 10),
  } : null;

  // ---- 4. 底部按钮（文本白名单 + 父容器 class）----
  const ALLOWED_BTN = ['发布', '修改', '保存草稿', '草稿箱', '取消', '确定'];
  out.bottom = [...document.querySelectorAll('button, [class*=btn]')]
    .filter(e => e.offsetParent !== null)
    .map(e => ({
      t: (e.textContent || '').trim(),
      c: String(e.className || '').slice(0, 60),
      parent: String(e.parentElement?.className || '').slice(0, 60),
      parentTag: e.parentElement?.tagName.toLowerCase(),
    }))
    .filter(x => ALLOWED_BTN.includes(x.t));

  // ---- 5. 状态标志 ----
  out.flags = {
    hasStalePrompt: /上次未发布的内容/.test(document.body.innerText || ''),
    hasCaptcha: !!document.querySelector('#tcaptcha_iframe_dy, iframe[src*=turing]'),
    planSwitchActive: !!document.querySelector('.creation-plan-join .switch__true-label.active'),
    // 只在「选择计划」行内取，且只比对已知计划名
    planRadios: (() => {
      const row = [...document.querySelectorAll('.creator-editor__form-item')].find(it =>
        (it.querySelector('.creator-editor__form-label')?.textContent || '').trim() === '选择计划');
      if (!row) return null;
      const KNOWN = ['文章计划', '热点计划'];
      return KNOWN.map(name => {
        const hit = [...row.querySelectorAll('.radio__select-label, label')]
          .find(e => (e.textContent || '').trim() === name);
        if (!hit) return { name, present: false, checked: null };
        const box = hit.closest('.radio') || hit.parentElement;
        return {
          name,
          present: true,
          checked: !!box?.querySelector('.radio__box.checked, .radio__box.active, input[type=radio]:checked'),
        };
      });
    })(),
  };

  // ---- 6. 截断记录（记录原始长度，不保留内容）----
  out.truncation = { modalChildren: mask?.querySelectorAll('*').length ?? 0 };

  console.log(JSON.stringify(out, null, 2));
  copy(JSON.stringify(out, null, 2));
})()
```

**这份脚本输出什么、不输出什么：**

| 输出 | 不输出 |
|---|---|
| origin、path、参数名 | 参数值、完整 URL |
| 弹窗子标签名、是否有 file input、img 协议 | 图片完整地址、弹窗文本全文 |
| 封面行结构、是否含 img | HTML 片段 |
| 按钮文本（白名单内）、父容器 class | 其他按钮文字、页面其他内容 |

**仍然采不到的（需要另外的只读方式）：**

| 缺失项 | 补救方式 | 风险 |
|---|---|---|
| 发布状态接口字段 | DevTools → Network → 筛选已发生的 `article` 请求，**只看已加载的响应，不重放** | 响应可能含敏感字段，需人工摘取 |

### 11.3 采集纪律

- 不主动重放请求
- 不为采证制造未保存内容
- 不切换真实文章状态
- 不整库导出 localStorage / IndexedDB
- 任何输出前逐字段确认是否允许
- 截断时记录**原始长度**，不保留被截断的内容
