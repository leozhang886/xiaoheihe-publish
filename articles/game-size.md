十年前，20G 算大游戏。

现在 100G 起步，150G 不稀奇。硬盘就那么大，装三个满了。

但你可能没想过：**那一百个 G 里到底装了什么。**

搞清楚了，就知道哪儿能省。

# 一、都是些什么

**音频。而且是没压缩的。**

一款 3A 的配音有好几种语言，每种几百小时对白。为了读取快，很多游戏直接存未压缩格式。

英语、法语、德语、西班牙语，全在你硬盘上。

**纹理。** 4K 贴图一张几十 MB，一个游戏几千张。开高画质靠它，代价也是它。

**预渲染过场。** 一段 4K 动画能吃掉几个 G。有些游戏这类文件占总量的一两成。

**重复资源。** 同一份资源在硬盘上存几份，放不同区块，为了减少读取跳转。

听着浪费，其实是拿空间换加载速度。

**PC 版没做精简。** 很多游戏主机优先开发，PC 版直接沿用同一套资源。

主机的硬盘是统一的，开发商不用考虑"用户 C 盘只剩 50G"。

# 二、为什么要留两倍空间

这个最好玩：预载 60G，装的时候提示空间不够。

原因不在 Steam 出 bug。

下载下来的是压缩包，装的时候要解压。

同一份内容，压缩状态 60G，解开可能 100G。

Steam 安装时要同时放得下这两份，装完才删压缩包。

**所以预留空间按解压后的体积算，不是下载体积。**

# 三、能省的两招

**第一招，看有没有单独的语言包。**

少数游戏把语言做成了独立 DLC，能在库里取消勾选，直接省一块。

但大部分游戏所有语言混一个包，Steam 层面删不掉。

**第二招，透明压缩。这个管用。**

推荐 [CompactGUI](https://github.com/IridiumIO/CompactGUI)（★9,039，10 月还在更新）。

它调用 Windows 自带的文件系统压缩。就是 `compact.exe` 那一套。

给整个游戏目录压一遍，文件还能照常用。

和压成 zip 的区别：**它是透明的。** 文件还是原来的路径和名字，游戏正常读写，不用先解压。

能省多少？

官方 README 举的例子是《方舟：生存进化》：

**169 GB → 91.2 GB**

官方说法是游戏目录最多能缩到 60%。

# 四、但有一条得先说清楚

README 里明确警告：

**用了 DirectStorage 的游戏，Windows 11 上不要用这个工具。**

原因很直接。DirectStorage 让游戏从 SSD 直读资源、绕过 CPU。

压过之后文件得先解压才能送过去，这个优势就没了。

所以压之前先查一下：你要压的这款用没用 DirectStorage。

# 五、两件别做的事

**一、别手删游戏目录里的文件。**

除了明确标着"语言包"的，其余文件游戏都可能引用。

删掉一个看着无关的 `.pak`，结局就是启动报错。

**二、压完要留神游戏更新。**

Steam 更新会往目录里写新文件，那部分是没压过的。

CompactGUI 有个后台监控能自动补压，但要你手动开。

# 六、我自己的做法

体积这件事的本质，是厂商拿硬盘空间换加载速度和开发成本。

这个你改不了。

但至少能分清两头：**哪里能省，哪里不能碰。**

我自己的习惯是装完一个大游戏就先压一遍，尤其是那种一百多 G 的。

第一次压完看那个数字掉下来，还挺解压。

你硬盘现在还剩多少？最大的那个占了多少 G？
