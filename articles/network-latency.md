先给结论：

游戏卡，跟你的宽带是多少兆基本没关系。

办了 1000M 宽带还卡，测速网站跑出 900 多兆，说明不了任何问题。

**测速测的是带宽，游戏要的是延迟。**

这是两件事。

# 一、带宽和延迟不是一回事

打个比方。

带宽是管子有多粗，延迟是水从这头到那头要多久。

游戏传的东西很少——你的操作、你的位置、别人的位置。

一局对战的数据量，比看一个视频小得多。

所以管子再粗也没用。卡的是水到得慢，不是管子细。

# 二、决定手感的是三个数

**延迟（ping）**：你的操作到服务器再回来要多少毫秒。

一般说 50ms 以内舒服，100ms 以上开始明显。

**抖动（jitter）**：延迟稳不稳。

它比延迟更伤人。

平时 30ms，偶尔跳到 200ms，你就会有那种"明明打中了却判定没中"的感觉。

**丢包（packet loss）**：数据包在路上丢了。

哪怕只丢 1%，表现就是瞬移、技能不响应、人物卡住再弹回来。

三个数里，抖动和丢包更容易被忽略，也更容易毁掉体验。

![](assets/latency-three.jpg)

# 三、测速网站测不出这些

测速网站干的事：下一个大文件，算速度。

它不测抖动，基本不测丢包，也不看路由。

所以你测出 900M，只能说明管子粗。

# 四、怎么测

第一步，ping 一下游戏服务器。

Windows 自带这个命令：ping -t 目标地址。

`-t` 是一直 ping，边玩边看。

看两个东西：时间那一列稳不稳，以及有没有「请求超时」。

偶尔一次超时可能是偶发。一直有就是丢包。

第二步，看是哪一跳出问题。

这一步很多人跳过，但它决定你能不能找运营商理论。

[WinMTR](https://github.com/WinMTR/WinMTR-Official)（★362）

经典的图形化工具，把 ping 和 tracert 合在一起，每一跳的丢包和延迟都能看到。

更好用的是 [trippy](https://github.com/fujiapple852/trippy)（★8,058，10 月还在更新）。

现代版的 mtr，终端界面，跨平台。

怎么看结果：

- 从第一跳就开始丢包 → 问题在你家（路由器、网线、WiFi）
- 前几跳都好、某一跳之后突然丢 → 线路或运营商的事

**这个判断很关键。** 没有这个证据，你打客服电话只会被敷衍。

还有个 [sping](https://github.com/LambdaBytes/sping)（★118），现代 ping 工具，带实时诊断。

# 五、最常见的四个原因

按遇到的频率排：

- **WiFi。** 无线丢包和抖动比有线大得多，能插网线就插网线。这一条能解决大部分问题
- **晚高峰。** 晚上八到十一点，小区线路拥堵，抖起来
- **跨运营商。** 你电信、服务器联通，中间那一跳就是瓶颈
- **路由器老了。** 用了五六年的路由器，满载时会自己丢包

前两个你改不了，后两个能。

# 六、先分清是谁的问题

有个简单办法：同时 ping 路由器和游戏服务器。

- 路由器也丢包 → 你家的问题（WiFi、网线、路由器）
- 路由器好、服务器丢 → 线路或服务器的问题

这一步能把责任分清楚，省下一堆瞎折腾。

# 七、测速网站的分数没意义

回到开头那句：

测速网站的分数，对你的游戏体验几乎没有解释力。

真正要看的是延迟、抖动、丢包三个数，以及丢在哪一跳。

把这三个数测出来，你才知道该换网线、换路由器，还是去投诉运营商。

你打游戏用 WiFi 还是有线？卡的时候测过丢包吗？
