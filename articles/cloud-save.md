Steam 云存档看起来很简单：自动上传，自动下载。

**但它有几种情况会让你丢进度。**

而且丢了之后，Steam 不一定告诉你。

# 一、云存档是怎么工作的

大致流程：

**退出游戏 → Steam 把本地存档和云端比对 → 有变化就上传。**

下次启动时反过来：**云端更新过，就下载。**

**关键在"比对"这一步。**

两边都有变化时，它不知道该信谁。

这就是冲突。

# 二、三种最常见的丢档场景

**第一种：两台机器都玩。**

在台式上玩了两小时，没等它上传完就关机；然后去笔记本接着玩。

**笔记本启动时，云端还是旧版本。**

你在笔记本上玩完，退出上传——**台式那两小时被覆盖了。**

第二种：离线玩。

断网状态下玩了很久，Steam 不知道你改了什么。

**联网后它可能直接拉云端覆盖本地。**

**第三种：存档太大。**

有些游戏存档本身几百 MB，甚至上 G。

**Steam 有大小限制，超了会被跳过，而且提示很不明显。**

# 三、怎么确认云存档有没有在工作

**在库列表里看游戏图标旁边的云朵标记。**

- 有云朵：这个游戏支持云存档
- 云朵带感叹号：出问题了
- 没有云朵：不支持

要看详细的：右键游戏 → 属性 → 通用，里面会显示云存档状态。

# 四、冲突了怎么救

Steam 会弹一个对话框让你选：

**本地存档 / 云端存档。**

**这一步千万别乱点。**

正确的做法是先保住本地文件：

- 找到本地存档位置，**复制一份到别的盘**
- 再去 Steam 里选
- 如果选错了，还能用备份还原

存档位置：常见在 `文档` 下，或者游戏安装目录的 `save` 文件夹。

**Steam 的云存档缓存在 `userdata\<你的ID>\` 下，也能翻。**

# 五、一个防丢的习惯

手动备份。

听起来原始，但最可靠。

写个简单的复制脚本，每次退游戏后把存档文件夹整个复制到另一个盘，加个日期。

**这事我吃过亏之后才开始做的。**

云存档的问题不在于不工作，而是**它出错的时候不吭声**。

# 六、还有一个坑：不同步的 DLC 和 MOD

带 MOD 的存档，在没装 MOD 的机器上读不出来。

**Steam 只负责传文件，不管你能不能读。**

所以换机器前，先确认 MOD 环境一致。
