![](assets/cover-displaymode.png)

画质设置页底下那一行，很多人是随便点的。

全屏、无边框窗口、窗口化，看着像同一件事的三种排版。

**其实它们走的是三条不同的显示路径。** 代价和收益都不一样。

![](assets/display-mode-paths.jpg)

这篇讲机制。看完你自己判断该选哪个。

# 独占全屏：路径最短

游戏直接把画面交给显示器，绕过 Windows 的桌面合成器。

好处是**延迟最低**，帧数通常最好。

可变刷新率（G-Sync / FreeSync）在这条路上也最可靠。

代价是切换成本高：

- Alt+Tab 出去会闪黑屏，切回来可能卡一下
- 多显示器用户常遇到"切出去就崩"
- 或者切回来发现第二个屏幕黑着

# 无边框窗口：多一道合成

游戏渲染到一个铺满屏幕的窗口里。

**画面要先经过 Windows 的桌面合成器（DWM），再送到屏幕。**

好处很实在：

- 切换几乎无感
- 多显示器友好
- 录屏、截图、语音悬浮窗都能正常叠在上面

代价就是那道合成环节。

早些年这意味着多一帧延迟、可能拿不到可变刷新率、帧数掉一点。

# 窗口化

普通窗口。

除非你有特殊理由，否则不用考虑。

# 关键：Windows 这些年改过好几次

如果你看到"无边框窗口性能差"的说法，先看它是什么时候写的。

微软后来给合成路径做了优化。现在的情况：

- Windows 10 有"**全屏优化**"，很多游戏在"独占全屏"时其实走一条更接近无边框的快速路径
- 较新的 Windows 上，无边框窗口**有可能**通过独立翻转（Independent Flip）拿到接近独占全屏的表现，同时保留可变刷新率

**"有可能"这三个字是重点。**

它取决于一堆东西：游戏的呈现方式、显卡驱动、显示器配置、有没有开 HDR、有没有叠加层。

Discord 的悬浮窗、录屏软件的浮窗，都算叠加层。

**同一台电脑上，A 游戏和 B 游戏的结果可以完全不同。**

所以网上那两种说法，都别全信：

- "无边框一定比全屏差 xx 帧"
- "现在无边框和全屏一样了"

# 怎么选

**默认先用游戏自带的独占全屏。**

理由很简单：这是开发者最可能针对优化过的路径。

你没遇到 Alt+Tab 崩溃、多显示器黑屏这类问题，就没有换的理由。

**出现下面这些情况，再考虑切无边框：**

- 你频繁切出去看攻略、回消息
- 用多显示器，切出切进老出问题
- 要录屏或者直播，独占全屏经常抓不到画面
- 窗口化之后有撕裂，但你不想开垂直同步

**切过去之后，核对三件事：**

1. 可变刷新率还生效吗（显示器 OSD 或驱动面板里能看）
2. 帧数掉了多少（游戏自带或者 RTSS 之类的工具）
3. 延迟有没有变差（靠手感，或者用支持延迟测量的工具）

三项都正常，就用无边框，体验更好。

**有一项明显变差，切回去。**

# 两个工具

**[Special K](https://github.com/SpecialKO/SpecialK)**（★2,111，6 天前还在更新）

被称为"PC 游戏瑞士军刀"。

跟这篇相关的是它能**强制游戏走更现代的呈现路径**。另外还能管帧率上限、HDR 和延迟。

功能强也意味着门槛高。它不算开箱即用的工具。

**[Borderless-Gaming](https://github.com/andrewmd5/Borderless-Gaming)**（★6,649）

把任意窗口程序一键变成无边框全屏，用起来简单。

**但这个项目 13 个月没更新了。**

现在还能用。遇到新游戏或者新系统的问题，别指望有人修。

这属于"star 高但要看最后提交时间"的典型例子。

# 我没有标准答案

这篇没给你"就用 XX"的结论，因为**这件事真的因游戏而异**。

给的是判断方法：

**先默认全屏，遇到问题再切，切完核对三项。**

VRR。帧数。延迟。

比你收藏十个"最佳画质设置"的帖子有用。

你平时用哪个模式？有没有遇到过切出去回不来？
